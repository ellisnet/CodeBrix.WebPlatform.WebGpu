================================================================================
THIRD-PARTY NOTICES: the wgpu crates that the CodeBrix.WebPlatform.WebGpu
package brings to an application's WebAssembly file
================================================================================

This file travels with the CodeBrix.WebPlatform.WebGpu.ApacheLicenseForever
package (tools/webgpu-crates/THIRD-PARTY-NOTICES-WebGpuCrates.txt; a build
program finds it beside itself as webgpu-crates/THIRD-PARTY-NOTICES-WebGpuCrates
.txt and reads it with WebGpuCrates.ReadNotices). It covers the package's crate
bundle: the Rust crates the package carries (as webgpu-crates.zip) and that the
platform's frontend build writes into the application's frontend beside the
platform's own crates. They are the `wgpu` crate, for WebGPU in the browser,
the `glam` crate, for vector and matrix maths, and every crate their
resolution names. Part 1 lists those compiled into an
application's WebAssembly file when its frontend uses `wgpu` with the features
this package's crate set names; Part 2 those that are carried but not compiled
in (they are needed so that cargo can resolve the frontend offline).

Many of these crates are also among the CodeBrix.WebPlatform platform's own
crates, at the same version and with the same content (the platform writes one
copy of each). They are listed here too, so that this file is complete for
what the package carries; the platform's notices
(PlatformCrates.ReadNotices) cover the platform's crates and not this package's.

Each third-party component stays under its own license; none is relicensed.
Where a crate offers a choice of licenses ("MIT OR Apache-2.0"), the entry
says which one is used.

The crate archive also holds codebrix-webgpu, the first-party crate of the
CodeBrix.WebPlatform.WebGpu repository (the WebGPU context, the canvas host
and the maths it re-exports from glam). It is covered by that repository's
own LICENSE (Apache-2.0) and is not third-party, so it is not listed below.
